# Issues round 2

## Context
Previously, the forder-refactor-plan.md and issues-resolution-plan.md were implemented. There are a few more things which need to be done. First consult the feedback below. If additional context is needed, then consult the two plan documents just referenced.

# Small items (all in conventions.py)
1. The method `_flatten_hamiltonian_data` should be renamed since now it either coerces `float` type or returns a `dict`. I guess this should be thought of as as something like "data normalization", but I'm open to other names for what this method does that are more appropriate.
2. Something seems funky with the `get_data_metadata` "refresh" logic. Can you double-check the implementation to confirm that `refresh=True` actually does trigger a reload from disk? If there is in fact a problem with the logic AND a significant refactor would be needed to fix it, I think we should just remove the "refresh" option.

# More complex items (affects conventions.py, and possibly circuit.py)
1. I now want to implement the logic for `compute_all_rotations_from_just_box_terms` in the case where a matrix element value is a dict. This is the most complex remaining todo item because it ends up touching multiple files.
2. If the matrix element value is a dict, then the keys of that dict will be "plane" tuples, and the values will either be (a) floats or (b) dicts again. In case (b), THOSE dicts will have keys that are "signatures" (see the definition of a signature in the "Issue 1" section of issues-resolution-plan.md), and values which are ALWAYS floats. The type annotation in the method signature needs to be updated to reflect these cases (maybe a type alias would help with this?), and the logic when hitting a dict should be to append the dict to the list of box_plus_box_dagger_rotations.
3. Downstream consumers of `compute_all_rotations_from_just_box_terms` need to be updated to parse cases where list elements are one of the kinds of dict that can show up (described in the previous item). This affects some tests in test_conventions.py, and the `load_magnetic_hamiltonian` method in conventions.py. The tests should be updated according to changes made in the previous item. The function `load_magnetic_hamiltonian` should be updated in the following way:
  1. Returns a dict which has the same key/value structure as the result of compute_all_rotations_from_just_box_terms(HAMILTONIAN_BOX_TERMS[dim_string][trunc_string]), except the top-level keys are the tuple `(state_1_bitstring, state_2_bitstring)` instead of `(plaquette_state_1, plaquette_state_2)` (i.e. the top-level keys are encoded plaquette states instead of decoded plaquette states).
4. Downstream consumers in ymcirc, run, and tests need to be able to parse this updated return type. We will start by doing this for `LatticeCircuitManager`, and then once that class has been updated, follow the patterns established there to fix any other broken consumers.
  1. The primary change that needs to happen in `LatticeCircuitManager` regards how `_build_mag_evol_circuit` interacts with the new dict type for the result of `load_magnetic_hamiltonian`. We should define a helper function which, given the plane and signature of the current plaquette in the lattice, extracts a list whose elements are of the form `(str, str, float)`. This should be the list of ONLY the matrix elements that matche the current plane and signature. If a matrix element has a plane key but no signature key, then assume it matches against all signatures. If a matrix element has neither plane nor signature keys, then assume it matches against all planes and signatures.
  2. Once this primary change has been made, other pieces of the codebase may break. There will need to be some rounds of testing, and fixing broken tests.
