# Remove "merged" behavior of `MatrixElementValue`, update `LatticeCircuitManager` logic to build magnetic Trotter step

## Context

In `ymcirc/conventions.py`, the `MatrixElementValue` type is currently a union of dictionary types where the value is either a float, or a dictionary which itself has either dictionary or float values. It is meant to store the data located loaded by the `_load_hamiltonian` function. However, it turns out that we need to retain full plane + signature information when working with matrix elements. This is because downstream, the `LatticeCircuitManager._resolve_hamiltonian_for_plaquette` class in `ymicrc/circuit.py` needs to be able to use `Plane` and `Signature` information (see those type aliases in `ymcirc/_abstract/lattice_data.py`) to filter matrix elements. Specifically, we need to prevent matrix elements that don't match the plane/signature of the current plaquette from being turned into Givens rotations when constructing the evolution circuits for the magnetic Trotter step.

## Desired behavior
The `_resolve_hamiltonian_for_plaquette` method should assume that every entry in the `hamiltonian` argument has a dictionary as a value; the keys of these dictionaries are `Plane` tuples, its the values are again dictionaries, where the lowest level of dictionary has `Signature` keys with float values. The `_resolve_hamiltonian_for_plaquette` needs to be updated to either know what the current plaquette's plane and signature are, or to be able to compute them. Then, based on the `plaquette`'s plane and signature, `_resolve_hamiltonian_for_plaquette` should ONLY retain matrix elements which match the plane and signature when constructing the `resolved` return list.

## Task
I have already updated the matrix element data files present in `ymcirc/_ymcirc_data/magnetic-hamiltonian-box-term-matrix-elements` to match the new matrix element data structure described. What needs to happen next is that all functions in the codebase which work with the `MatrixElementValue` type need to be updated based on the description above. Additionally, a function to compute a plaquette's signature may need to be implemented (although I think `Plaquette.control_links_per_vertex` might already do this, though there might be some subtleties with the return type). Further, the logic for resolving the hamiltonian for a plaquette must be updated so that plaquettes in the wrong plane, with the wrong signature, DO NOT end up being turned into Givens rotations when constructing the magnetic Trotter step. Finally, tests and docstrings should be updated to reflect changes in behavior.
